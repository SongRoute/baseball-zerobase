## 1. 제품 목표

MLB 경기를 시청하는 사용자가 매 투구 직전에 다음 질문을 탐색할 수 있게 한다.

> 현재 경기 상태와 실제 라인업을 고려할 때, 이 선발투수가 보유한 구종 중 어떤 공이 어느 존에 도달하면 이닝 종료까지의 기대실점을 가장 낮출 수 있는가?

시스템은 투수의 보유 구종과 타자 기준 상대좌표 13존의 모든 조합을 평가하고, 전체 행동 순위와 신뢰도를 제공한다. 과거 경기 리플레이 MVP에서는 추천과 실제 투구의 구종 및 도착 존을 비교한다.

추천은 최적성을 증명하거나 투수의 실제 의도를 판정하지 않는다. 데이터와 모델이 지지하는 조건부 공략 가치를 제시하는 분석 도구다.

## 4. 해석 계약

Statcast에는 포수가 요구한 목표 위치가 없다. 따라서 실제 도착 위치를 투수의 의도와 동일하게 볼 수 없다.

시스템의 행동 `구종 × 13존`은 다음 조건부 질문을 나타낸다.

> 이 투수가 해당 구종을 던졌고 공이 해당 존에 도달했다고 가정할 때, 이후 이닝 종료까지의 기대실점은 얼마인가?

이에 따라 다음 원칙을 지킨다.

- 추천 존은 공략 지점이며 포수의 사인 또는 투수의 의도를 의미하지 않는다.
- 실제 도착 존과 추천 존이 다르더라도 이를 선택 실수라고 표현하지 않는다.
- 특정 존의 과거 사용 빈도와 도달 가능성은 후보 제외, 추천 순위, 페널티에 사용하지 않는다.
- 특정 `투수-구종-존` 조합의 학습 근거가 부족하면 제거하지 않고 불확실성을 높이거나 `근거 부족`으로 표시한다.
- 실제 투구 결과 한 건으로 추천의 옳고 그름을 판단하지 않는다.

## 5. 데이터 범위와 분할

### 5.1 원천 데이터

새 프로젝트가 MLB Statcast와 MLB 경기 메타데이터를 직접 수집한다.

- Statcast 투구 단위 데이터
- 공식 선발투수 정보
- 경기 선발 라인업과 실제 교체 기록
- 경기 및 타석 식별자
- 투구 전후 카운트, 아웃, 주자, 득점 상태

원천 데이터는 수정하지 않으며, 수집 시각, 요청 범위, 파일 체크섬을 manifest에 기록한다.

### 5.2 대상 투구

- 공식 선발투수가 선발 등판에서 던진 투구만 포함한다.
- 해당 선발투수가 교체되기 전까지의 투구만 포함한다.
- 구원 등판한 투구는 제외한다.
- 스프링 트레이닝은 제외한다.
- 자동 볼, 자동 스트라이크, 고의사구 등 일반 투구 전략과 다른 이벤트는 별도 플래그를 기록하고 추천 학습에서는 제외한다.

### 5.3 선발투수 및 구종 자격

초기 자격 기준은 다음과 같다.

- 선발투수: 추천 시점 이전 최근 2개 시즌 합계 1,000구 이상
- 현재 시즌: 추천 시점 이전 300구 이상
- 보유 구종: 추천 시점 이전 최근 2개 시즌 100구 이상이며 구사율 5% 이상

시즌 초 현재 시즌 300구 조건을 충족하지 못한 경우에도 최근 2개 시즌 1,000구 조건을 충족하면 이전 시즌 축소 추정 프로필로 추천할 수 있다. 이 경우 신뢰도에 시즌 초 표본 부족을 반영한다.

임계값은 내부 롤링 검증에서 미리 정의한 후보 집합을 비교하여 최종 선택한다. 잠금 테스트에서는 변경하지 않는다.

### 5.4 시간 분할

내부 모델 선택은 롤링 검증으로 수행한다.

| Fold | 학습 | 검증 |
|---|---|---|
| 1 | 2022 정규시즌 | 2023 정규시즌 |
| 2 | 2022~2023 정규시즌 | 2024 정규시즌 |
| 3 | 2022~2024 정규시즌 | 2025 정규시즌 |

최종 모델은 2022~2025 정규시즌 전체로 재학습한다.

잠금 테스트는 다음 두 집합이다.

| 테스트 | 기간 | 역할 |
|---|---|---|
| Test A | 2025 포스트시즌 | 정상급 타선과 포스트시즌 환경의 스트레스 테스트 |
| Test B | 2026-03-25~2026-05-31 정규시즌 | 미래 시즌 일반화의 주 평가 |

Test A와 Test B는 모델 선택, 특징 선택, 임계값 조정, 확률 보정에 사용하지 않는다. 잠금 테스트 실행은 최종 모델과 평가 프로토콜을 고정한 뒤 한 번 수행한다.

## 6. 투구 전 상태 스냅샷

각 학습 및 추천 행은 투구 직전에 알 수 있었던 정보만 포함한다.

### 6.1 경기 상태

- 볼 수와 스트라이크 수
- 아웃 수
- 1루, 2루, 3루 주자 존재 여부
- 이닝
- 점수 차
- 수비 팀
- 현재 타순 인덱스

### 6.2 현재 활성 라인업

- 현재 타자와 이후 타자의 순서
- 각 타자의 약점 유형
- 각 타자의 위협도
- 각 타자의 타석 방향

추천 시점 이후 실제 발생한 대타나 대주자를 미리 사용하지 않는다. 시뮬레이션에서는 추천 시점의 활성 라인업이 이닝 종료까지 유지된다고 가정한다.

리플레이 평가 중 다음 사건이 발생한 이후의 비교는 주요 평가에서 제외하고 별도 분석으로 보존한다.

- 선발투수 교체
- 대타 또는 대주자 투입
- 부상 등 비정상 경기 중단

### 6.3 투수 개인 프로필

추천 시점 이전 데이터만 이용하여 다음을 계산한다.

- 보유 구종 목록
- 구종별 평균 구속, 무브먼트, 릴리스 특성의 축소 추정값
- 구종별 사용률과 결과 분포
- 투수 손잡이
- 최근 장기 추세
- 공유 모델용 투수 표현

추천 입력에는 현재 투구가 끝난 뒤 측정되는 실제 구속, 무브먼트, 릴리스, 도착 위치를 넣지 않는다. 후보 구종의 물리 특성은 투구 전까지 알려진 개인 프로필 분포로 표현한다.

### 6.4 당일 누적 상태

현재 투구 이전까지 당일 경기에서 관측된 정보만 이용한다.

- 누적 투구 수
- 당일 구종 사용 비율
- 구종별 평균 구속과 장기 프로필 대비 변화
- 구종별 무브먼트 변화
- 최근 볼, 스트라이크, 헛스윙, 강한 타구 요약

당일 상태는 선발투수의 피로와 구질 변화를 반영하지만, 현재 투구 이후 정보는 포함하지 않는다.

### 6.5 시간 누수 방지

모든 프로필과 특징 행에 `as_of_timestamp`를 기록한다. 자동 검증은 모든 입력 특징의 기준 시각이 추천 대상 투구 시각보다 앞서는지 확인한다.

## 7. 상태와 행동 공간

### 7.1 시뮬레이터 상태

```text
GameState =
  count
  + outs
  + runners
  + inning
  + score differential
  + batting-order index
  + active lineup
  + pitcher pitch count
  + pitcher day-state summary
```

상태는 이닝 종료 시 terminal이 된다.

### 7.2 행동 공간

```text
Action = pitcher-owned pitch type × batter-relative 13-zone
```

13존은 다음과 같다.

- 스트라이크존 내부 3×3의 9개 존
- 외곽 위, 아래, 몸쪽, 바깥쪽의 4개 존

좌타자와 우타자의 좌우 좌표를 반전하여 항상 타자 관점의 몸쪽과 바깥쪽을 사용한다.

후보 행동은 자격을 충족한 투수 보유 구종과 모든 13존의 곱이다. 특정 존 사용 빈도나 도달 가능성으로 후보를 제거하지 않는다.

## 8. 모델링 접근법

### 8.1 주 모델: 계층적 공유 모델

전체 자격 선발투수 데이터를 공유하여 공통적인 야구 패턴과 희소 결과를 학습하고, 투수 개인 프로필과 당일 상태를 조건으로 개인화한다.

완전한 투수별 독립 모델은 기준 비교 실험으로만 사용한다. 독립 모델은 개인 특성을 강하게 표현할 수 있지만 행동별 표본이 부족하고 희소 결과 학습과 유지보수가 어렵다.

공유 모델은 다음 방식으로 개인화를 보존한다.

- 투수 보유 구종별 물리 프로필
- 투수의 장기 및 최근 성과
- 투수 표현 벡터
- 당일 누적 상태
- 데이터가 충분한 투수에 더 높은 개인 정보 가중치
- 데이터가 적을 때 유사 투수와 리그 평균으로 축소

### 8.2 타자 표현

타자는 `약점 유형`과 `위협도`로 분리한다.

약점 유형은 공략 방식의 차이를 표현한다.

- 구종군별 헛스윙, 접촉, 파울 비율
- 타자 기준 존별 반응
- 투수-타자 손잡이 조합별 상대 반응
- chase와 zone-contact 성향

약점 유형에는 타율, wOBA, 홈런 수처럼 절대 공격 능력을 직접 나타내는 값을 넣지 않는다.

위협도는 타자가 얼마나 위험한지를 표현한다.

- 출루 능력
- 장타 능력
- 타구 품질
- 장기 성적과 최근 성적의 축소 추정값

### 8.3 행동 모델

행동 모델은 실제 MLB 선발투수 선택 분포를 추정한다.

```text
P(actual pitch type, actual arrival zone | pre-pitch state, pitcher profile)
```

행동 모델은 추천 후보를 제한하지 않는다. 이닝 시뮬레이션에서 현재 후보 행동 이후의 실제적인 후속 투구를 샘플링하고, 추천과 실제 MLB 선택의 정합성을 평가하는 기준으로 사용한다.

### 8.4 계층적 투구 전이모델

단일 결과 분류기가 아니라 공유 표현과 여러 조건부 헤드로 다음 과정을 모델링한다.

1. `Swing Head`
   - `P(swing | state, action)`
2. `Contact Head`
   - `P(contact | swing, state, action)`
3. `Called Result Head`
   - `P(ball, called strike, HBP | no swing, state, action)`
4. `Contact Result Head`
   - `P(foul, in-play | contact, state, action)`
5. `Batted Ball Head`
   - 인플레이 타구 품질과 아웃, 단타, 장타, 홈런 분포
6. `Plate Appearance Head`
   - 타석 종료 여부와 볼넷, 삼진 등 종료 결과
7. `Runner Advancement Head`
   - 다음 주자 상태, 추가 아웃, 발생 득점

공유 표현은 경기 상태, 현재 타자 표현, 투수 프로필, 당일 상태, 행동을 입력으로 사용한다.

희소한 홈런, 장타, 병살 결과는 별도 헤드와 클래스 가중 손실로 학습한다. 모델은 전체 확률 분포를 출력하며, 각 조건부 분포는 확률 합과 가능한 상태 전이 규칙을 만족해야 한다.

### 8.5 학습 손실과 확률 보정

- 범주형 헤드: Cross Entropy를 기본으로 하고 내부 검증에서 Focal Loss와 비교
- 연속 타구 품질: Huber Loss
- 희소 결과: 사전 정의된 클래스 가중치 후보를 내부 롤링 검증으로 선택
- 확률 보정: 각 내부 검증 Fold에서 temperature scaling 또는 isotonic calibration을 비교
- 행 가중치: 특정 투수나 경기의 과대표현을 줄이는 투수-경기 균형 가중치

모델 선택의 우선순위는 정확도보다 확률 보정과 시뮬레이터 분포 적합성이다.

### 8.6 기준 모델

다음 기준 모델을 반드시 함께 평가한다.

- 리그 평균 조건부 전이 테이블
- LightGBM 기반 투구 결과 모델
- 실제 투구 이후 이닝 종료까지의 실점을 직접 예측하는 지도학습 가치 모델
- 충분한 표본을 가진 일부 투수의 독립 전이모델

직접 가치 모델은 추천 주 모델로 사용하지 않고 선택 편향과 공유 전이모델의 성능을 비교하는 기준으로 사용한다.

## 9. 이닝 시뮬레이터

### 9.1 기본 계산

각 후보 행동을 현재 투구에 한 번 고정한 뒤, 실제 활성 라인업 순서를 따라 이닝 종료까지 Monte Carlo 시뮬레이션한다.

```text
for candidate in pitcher_owned_pitch_types × all_13_zones:
    first pitch = candidate
    sample first outcome from transition model
    while inning is not over:
        sample next action from behavior model
        sample next outcome from transition model
        update count, outs, runners, runs, lineup index, and day state
    record inning runs
```

MVP의 주 가치는 현재 한 번의 선택만 바꾼 `single-decision value`다. 이후 투구는 행동 모델이 추정한 실제 MLB 선택 분포를 따른다.

후속 단계에서는 행동 모델 분포에서 크게 벗어나지 않는 보수적 정책 개선을 별도 실험한다. 이 값은 `improved-policy value`로 분리해 저장하며 MVP의 주 추천값과 섞지 않는다.

### 9.2 출력 통계

각 후보 행동에 대해 다음을 계산한다.

- 평균 이닝 실점
- 중앙값 이닝 실점
- 무실점 확률
- 2점 이상 대량 실점 확률
- 기대실점 신뢰구간
- 모델 앙상블 간 불일치
- 학습 근거 표본량

### 9.3 불확실성

시간 블록과 투수 단위 부트스트랩으로 학습한 모델 앙상블을 사용한다. 각 앙상블 모델과 Monte Carlo 시뮬레이션의 변동을 분리해 기록한다.

신뢰도는 다음 증거를 결합하여 결정한다.

- 후보 행동의 학습 근거 표본량
- 앙상블 모델 간 기대실점 순위 합의
- Top-1과 차선책의 신뢰구간 분리 정도
- 시간 Fold 간 추천 순위 안정성

특정 존의 도달 가능성과 과거 사용 빈도는 신뢰도에 포함하지 않는다.

## 10. 순위와 추천 출력

후보 행동은 다음 보수적 점수로 정렬한다.

```text
ranking_score =
  expected inning runs
  + model uncertainty penalty
  + insufficient evidence penalty
```

도달 가능성, 제구 난이도, 특정 존 사용 빈도 페널티는 없다.

신뢰도 상태는 다음과 같다.

- `high`: 표본과 모델 합의가 충분하고 Top-1 우위가 명확함
- `medium`: 추천 우위가 있으나 일부 신뢰구간이 겹침
- `low`: 표본 부족 또는 모델 간 의견 차이가 큼
- `abstain`: 의미 있는 우위를 가진 행동을 결정할 수 없음

Top-1과 차선책의 신뢰구간이 실질적으로 겹치면 공동 추천으로 표시한다.

추천 결과 계약은 다음 필드를 포함한다.

```json
{
  "state_id": "game-pitch-snapshot",
  "value_type": "single-decision",
  "recommendations": [
    {
      "rank": 1,
      "pitch_type": "SL",
      "zone": "low_away",
      "expected_inning_runs": 0.28,
      "expected_inning_runs_interval": [0.23, 0.36],
      "ranking_score": 0.31,
      "confidence": "medium",
      "evidence": {
        "pitcher_pitch_samples": 842,
        "action_evidence_samples": 74,
        "ensemble_rank_agreement": 0.81
      }
    }
  ]
}
```

## 11. 리플레이 비교

과거 경기의 각 투구 직전 상태를 재구성하고 추천을 생성한 뒤 실제 투구와 비교한다.

### 11.1 비교 지표

- 정확 일치: 실제 구종과 실제 도착 존이 Top-1과 모두 일치
- 구종 일치: 실제 구종이 Top-1 구종과 일치
- Top-k 일치: 실제 구종-도착 존 행동이 추천 상위 후보에 포함
- 조건부 가치 차이:

```text
decision_gap =
  actual pitch and arrival-zone expected inning runs
  - recommended action expected inning runs
```

`decision_gap`은 추천 대비 실제 도착 행동의 조건부 가치 차이다. 투수의 의도, 사인 선택, 제구 실수를 판정하는 지표가 아니다.

### 11.2 결과 해석

추천과 일치한 실제 투구의 결과가 더 좋았는지는 집계 수준에서만 보조 분석한다. 단일 투구 또는 단일 경기 결과를 추천 정답으로 사용하지 않는다.

## 12. 평가 체계

### 12.1 구성요소 평가

| 구성요소 | 주요 지표 |
|---|---|
| 타자 약점 유형 | 시간 Fold 안정성, 유형별 상대 반응 차이, 해석 가능성 |
| 타자 위협도 | 미래 구간 공격 성과 순위 및 확률 보정 |
| 행동 모델 | 실제 선택 Top-k, Log Loss, Brier Score, Calibration Error |
| 전이모델 | 헤드별 Log Loss, Brier Score, Calibration Error, 희소 결과 Recall |
| 주자 진루 모델 | 다음 주자·아웃 상태 정확도, 득점 오차 |
| 시뮬레이터 | 예상 이닝 실점 분포와 실제 분포의 적합도 |
| 불확실성 | 신뢰도 구간별 실제 예측 오차의 단조 관계 |

홈런, 장타, 병살, 볼넷, 삼진 등 전략적으로 중요한 희소 결과를 별도로 보고한다.

### 12.2 야구 상식 점검

다음 패턴은 학습 강제 규칙이 아니라 이상 탐지용 검수 항목이다.

- 3-0에서 스트라이크존 내부 행동 가치 상승
- 0-2에서 외곽 존 가치 상승 가능
- 병살 가능 상황에서 낮은 공의 가치 변화
- 강한 타자 상대 시 위험 존 가치 하락
- 동일 투수라도 타자 유형과 이후 타순에 따라 추천 변화
- 투구 수와 당일 상태 변화에 따른 추천 변화

### 12.3 잠금 테스트

잠금 테스트에서는 다음을 보고한다.

- 확률 보정 유지 여부
- 실제 MLB 선택과 추천 Top-k 정합성
- 행동별 기대실점 순위 안정성
- 신뢰도와 실제 모델 오차 관계
- 새로운 구종 또는 구질 변화에 대한 실패율
- 리플레이 비교 분포

2025 포스트시즌은 표본이 작고 정상급 선수 비율이 높으므로 스트레스 테스트로 해석한다. 2026년 3~5월은 미래 일반화의 주 평가다.

### 12.4 중단 기준

다음 중 하나라도 발생하면 추천 엔진 확대를 중단하고 해당 구성요소를 개선한다.

- 주요 전이 확률 보정이 리그 평균 기준 모델보다 나쁨
- 홈런, 장타, 병살 등 주요 희소 결과를 사실상 예측하지 못함
- 시뮬레이터 예상 실점 분포가 실제 이닝 실점 분포와 유의미하게 불일치
- 내부 시간 Fold마다 추천 순위가 과도하게 변함
- 신뢰도와 실제 모델 오차 사이에 유의미한 관계가 없음
- 시간 누수 또는 잠금 테스트 오염이 발견됨

## 14. 테스트 전략

- 상태 재구성: 볼카운트, 주자, 아웃, 점수, 타순이 실제 경기와 일치
- 시간 누수: 모든 특징의 `as_of_timestamp`가 추천 대상 투구보다 이전
- 상대좌표: 좌타자와 우타자의 좌우 존 변환이 일관됨
- 행동 후보: 보유 구종과 모든 13존의 곱이며 존 빈도로 제거되지 않음
- 확률 불변식: 모든 조건부 분포의 합이 1이고 불가능한 전이는 0
- 시뮬레이터 불변식: 아웃은 감소하지 않고, 타순은 정상 순환하며, 이닝은 반드시 종료
- 결정론: 동일 모델, 입력, seed에서 동일 결과
- 잠금 테스트 보호: 개발 및 학습 명령이 잠금 테스트 데이터에 접근하지 못함
- 통합 리플레이: 실제 경기 한 이닝을 처음부터 끝까지 재생하고 모든 투구 전 상태를 생성

리플레이 MVP는 웹페이지를 포함하지 않는다. 다음 흐름이 재현 가능하게 동작하면 완료다.

```text

→ 각 투구 직전 상태와 활성 라인업 재구성

→ 실제 투구와 비교한 리플레이 리포트 생성
```

첫 구현 계획의 범위는 Milestone 1의 데이터 기반과 Milestone 2의 평가 가능한 기준 시스템까지다. 이 범위는 `codex/milestone-1-2`에서 구현과 검증이 완료되었으며, 다음 계획은 개인화 전이모델과 추천 엔진을 별도 범위로 진행한다.
